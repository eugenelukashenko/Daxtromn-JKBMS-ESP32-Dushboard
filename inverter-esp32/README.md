# Daxtromn AOH-3.2KVA: RS-232 -> ESP32 -> MQTT

Інвертор: Daxtromn 3 кВт / 3,2 кВА, 24 В, гібридний, MPPT 80 А. Порт зв'язку: RJ45, справжній RS-232.
Мета: ESP32 опитує інвертор по RS-232 і через Wi-Fi (STA до локальної точки доступу) публікує дані в локальний MQTT-брокер `10.100.202.5`.

Малюнок розпіновки: `inverter_rj45_pinout.png`.

## Розпіновка RJ45 інвертора

Виміряно мультиметром, інвертор увімкнений, мінус щупа на Pin 8 (2026-10-20).
Нумерація: штекер контактами до себе, фіксатор унизу, Pin 1 зліва.

| Pin | Сигнал (з боку інвертора) | У спокої | Напрямок | Статус |
|---|---|---|---|---|
| 1 | TX інвертора (вихід) | -12,8 В | інвертор -> ПК/модуль | виміряно |
| 2 | RX інвертора (вхід) | 0 В | ПК/модуль -> інвертор | виміряно |
| 3 | не підключений | - | - | зі старої схеми, не виміряно |
| 4 | +12 В живлення модуля | +12,8 В | вихід інвертора, до 0,6 А | виміряно |
| 5, 6, 7 | не підключені | - | - | зі старої схеми, не виміряно |
| 8 | GND | 0 | спільна земля сигналу | виміряно |

Висновок: рівні ±12,8 В, тобто справжній RS-232. ESP32 (3,3 В) і FT232RL (TTL) напряму підключати **не можна**, тільки через MAX3232 (3,3 В).
Підписи "RX/TX" на знімку з пінами (Pin 1 RX, Pin 2 TX) дано з боку під'єднаного пристрою, а не інвертора.
Pin 8 може бути гальванічно відв'язаний від батареї інвертора: не з'єднувати його з іншою землею без перевірки.

## Схема підключення

Перетворювач рівнів: готовий модуль RS-232 -> UART на MAX3232 (arduino.ua, prod3271). Конденсатори на модулі вже є.
На боці RS-232 у модуля **DB9 female**, не RJ45: дроти від RJ45 інвертора підключаються до пінів DB9 (перехідником або паянням).
Модуль працює як "комп'ютер" (DTE): DB9 pin 2 = RX модуля, pin 3 = TX модуля, pin 5 = GND (так само в документі MPI).

| Інвертор RJ45 | DB9 female модуля | TTL-піни модуля | ESP32 (DevKit) | FT232RL (діагностика з ПК) |
|---|---|---|---|---|
| Pin 1 (TX інвертора) | pin 2 (RX модуля) | RXD модуля | GPIO16 (RX2, "D16") | RXD |
| Pin 2 (RX інвертора) | pin 3 (TX модуля) | TXD модуля | GPIO17 (TX2, "D17") | TXD |
| Pin 8 (GND) | pin 5 (GND) | GND | GND | GND |
| | | VCC модуля | 3V3 (не 5 В) | 3,3 В (перемичка на 3V3) |
| Pin 4 (+12,8 В) | | | DC/DC 12 -> 5 В -> VIN | |

Примітки:
- Підписи TTL-пінів модуля (з боку модуля чи МК) на сторінці магазину не вказані. Якщо відповіді немає, поміняти місцями RXD/TXD модуля і/або дроти до Pin 1 і Pin 2 інвертора (це безпечно).
- **Модуль живити від 3,3 В ESP32.** При живленні 5 В його TX дає 5 В на GPIO ESP32 і може його пошкодити. Відгук на сторінці каже, що на 3,3 В модуль працює; перевірити мультиметром (TTL-вихід у спокої ≈ 3,3 В).
- Не вмикати micro-USB модуля одночасно з живленням по пінах.
- Перевірка: на DB9 pin 3 (TX модуля) у спокої має бути від'ємна напруга (≈ -5...-10 В).
- Pin 4 (+12,8 В) на модуль і на ESP32 напряму не подавати: тільки через DC/DC 12 -> 5 В на VIN ESP32. Налаштувати DC/DC на 5,0 В без навантаження, потім підключати ESP32. Не вмикати USB ESP32 одночасно з живленням від інвертора. Захист на вході як у старій схемі: запобіжник 0,5 А, P-MOSFET від переполюсовки, TVS SMBJ15A, конденсатор 220 мкФ / 25 В. Струм Pin 4 "до 0,6 А" зі старої схеми не підтверджено: виміряти під навантаженням.
- Запас по струму: ESP32 у Wi-Fi дає піки до ~250 мА на 5 В.
- Не використовувати GPIO 0, 2, 12, 15 (strapping) і `TX0/RX0` (зайняті USB).
- Wi-Fi тільки 2,4 ГГц.
- Без готового модуля (MAX3232 на макетці): T1IN = TX, R1OUT = RX, R1IN/T1OUT = RS-232 сторона, конденсатори 100 нФ: C1 між 1 і 3, C2 між 4 і 5, C3 від V+ (2) на GND, C4 від V- (6) на GND.

## Плата ESP32

ESP32-WROOM-32D на DevKit-платі з гвинтовим роз'ємом (CH340, USB-C). Підходить: 3,3 В логіка, Wi-Fi STA, вільний UART2 (GPIO16/17).
USB-UART адаптер FT232RL (USB-C, перемичка 3,3/5 В): тільки TTL, використовується для діагностики з ПК через модуль MAX3232.

## Протокол (визначено 2026-11-05)

**PI30 (Voltronic/Axpert), 2400 бод, 8N1, без парності.** Інвертор відповів на `QPI`: `(PI30`. Кадр: команда + CRC16/XMODEM (2 байти) + `\r`; відповідь `(` ... CRC `\r`. CRC відповідей перевірено, збігається. Інвертор приймає команди і з CRC, і без нього (відповідь однакова). PACE на 9600 не відповідає.
Тест: `probe_protocol.py` через CH341 (FT232 виявився несправним) + модуль MAX3232, дроти запаяні (до цього були збої через контакт).

| Команда | Відповідь (приклад) | Зміст |
|---|---|---|
| `QPI` | `(PI30` | протокол PI30 |
| `QMOD` | `(L` | режим: L = мережа (Line) |
| `QID` | `(q535q535q53535` | серійний номер |
| `QMD` | `(NAK` | не підтримується |
| `QPIGS` | `(228.3 50.0 228.3 50.0 0048 0011 001 428 27.09 000 100 045 00.1 000.1 00.00 00000 00010001 00 00 00000 110` | поточні дані |
| `QPIRI` | `(220.0 13.0 220.0 50.0 13.6 3000 3000 24.0 22.0 20.0 28.2 27.1 2 40 040 1 0 2 1 01 0 0 27.0 0 1` | номінальні параметри |

`QPIGS` (стандартний PI30): напруга мережі 228,3 В; частота мережі 50,0 Гц; вихід 228,3 В / 50,0 Гц; видима потужність 48 ВА; активна 11 Вт; навантаження 1 %; шина 428 В; акумулятор 27,09 В; струм заряду 0 А; ємність 100 %; температура радіатора 45; струм PV 0,1 А; напруга PV 0,1 В; напруга акумулятора від SCC 0,00 В; струм розряду 0 А; статус `00010001`; PV-потужність 0 Вт.
`QPIRI`: мережа 220 В / 13 А, вихід 220 В / 50 Гц / 13,6 А, 3000 ВА / 3000 Вт, акумулятор 24 В, перезаряд 22 В, відсічка 20 В, заряд 28,2 В, плаваючий 27,1 В.
Не перевірено: `QPIWS` (попередження), `QFLAG`, команди налаштувань. Документ MPI 5.5K у цій папці описує схожі, але не ідентичні поля.

## MQTT

Брокер `10.100.202.5` (перевірено 2026-10-20 з 10.100.202.58):
- пінгується (1-58 мс);
- порти 1883, 8883, 9001 відхиляють з'єднання (refused);
- відкриті 21, 22, 80, 111, 139, 443, 445, 554, 5000, 5001, 9443 (схоже на NAS), MQTT-брокера серед них не знайдено.

Брокер потрібно підняти (Mosquitto на цьому хості) або вказати правильні хост/порт/логін.
