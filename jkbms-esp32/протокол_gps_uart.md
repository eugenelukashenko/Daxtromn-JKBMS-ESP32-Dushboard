# Протокол порту GPS на JK-BMS (UART)

Результат реального зчитування з BMS (8 комірок, 26 В), 2026-11-09.

## Фізичний рівень

| Параметр | Значення |
|---|---|
| Інтерфейс | UART, логіка 3.3 В (TTL) |
| Швидкість | 115200, 8N1 |
| Рівень спокою на RX і TX | 3.2 В (високий) |
| Пін VCC | напруга батареї (25 В), **не підключати** |
| MAX3232 | не потрібен |

Підключення (BMS → CH341 в UART-режимі, 3.3 В):

```text
JK-BMS GPS         CH341
GND  ───────────── GND
TX   ───────────── RXD
RX   ───────────── TXD
VCC  ───────────── НЕ ПІДКЛЮЧАТИ
```

Примітка: у цьому випробуванні лінії RX/TX були поміняні місцями відносно першої схеми. Якщо відповіді немає, спробуйте поміняти їх.

BMS сама нічого не шле, вона відповідає тільки на запит.

## Запит

Modbus-подібний кадр, адреса 1, функція 0x10, CRC16 Modbus (little-endian).

| Мета | Кадр (без CRC) |
|---|---|
| Налаштування BMS (тип 1) | `01 10 16 1E 00 01 02 00 00` |
| Дані в реальному часі (тип 2) | `01 10 16 20 00 01 02 00 00` |

Далі додається CRC16 Modbus (2 байти, молодший першим). На адресу 0, на швидкостях 9600/19200/38400 і на кадр `AA 55 90 EB` відповіді не було.

## Відповідь

Кадр 300 байт (з хвостом приходить 308), заголовок `55 AA EB 90`.

| Offset | Поле |
|---|---|
| 0–3 | заголовок `55 AA EB 90` |
| 4 | тип кадру (1 — налаштування, 2 — дані) |
| 5 | лічильник кадру |

### Кадр типу 2 (дані в реальному часі)

Little-endian. Розкладка збіглася з вимірами для 8 комірок.

|---|---|---|---|
| 6 | uint16 × 32 | мВ | напруги комірок (невикористані = 0) |
| 144 | int16 | 0.1 °C | температура MOS |
| 150 | uint32 | мВ | напруга пакета |
| 158 | int32 | мА | струм (мінус = розряд, знак не перевірено на навантаженні) |

| 164 | int16 | 0.1 °C | температура T2 |

## Скрипт

Код зчитування:

```python
import serial, time, struct, glob

def crc16(d):
    c = 0xFFFF
    for x in d:
        c ^= x
        for _ in range(8):
            c = (c >> 1) ^ 0xA001 if c & 1 else c >> 1
    return c.to_bytes(2, "little")

b = bytes([1, 0x10, 0x16, 0x20, 0, 1, 2, 0, 0])
req = b + crc16(b)

s = serial.Serial(sorted(glob.glob("/dev/ttyUSB*"))[0], 115200, timeout=0.2)
s.reset_input_buffer()
s.write(req)
time.sleep(1.5)
r = s.read(4096)
s.close()

i = r.find(b"\x55\xaa\xeb\x90")
f = r[i:i + 300]
if f[4] == 2:
    cells = [struct.unpack_from("<H", f, 6 + 2 * k)[0] for k in range(32)]
    print("cells mV:", [c for c in cells if c])
    print("total V:", struct.unpack_from("<I", f, 150)[0] / 1000)
    print("current A:", struct.unpack_from("<i", f, 158)[0] / 1000)
    print("T_mos:", struct.unpack_from("<h", f, 144)[0] / 10,
          "T1:", struct.unpack_from("<h", f, 162)[0] / 10,
          "T2:", struct.unpack_from("<h", f, 164)[0] / 10)
    print("SOC %:", f[173])
    print("cycles:", struct.unpack_from("<I", f, 182)[0])
```

Примітка: `jk_scan.py` у цій папці працює з іншим протоколом (RS485 V2.0, кадри `4E 57`) і на порту GPS відповіді не отримав.
