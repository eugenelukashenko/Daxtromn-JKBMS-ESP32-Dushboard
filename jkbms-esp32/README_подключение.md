# Подключение JK-BMS к ESP32 и инвертору Daxtromn

## Исходные данные

По фотографиям установлено, что у данной версии JK-BMS отсутствует отдельный разъём CAN/RS485. Доступен только разъём **GPS**, который производитель маркирует как **RS485 (By default)**.

На изображении разъём GPS имеет следующую распиновку:

```text
GPS connector (4 pin)

1 — GND
2 — RX
3 — TX
4 — VCC
```

Несмотря на надпись **RS485 (By default)**, подписи выводов RX/TX указывают на последовательный интерфейс UART. На некоторых версиях JK-BMS этот порт может программно переключаться между UART и RS485.

## Вариант 1 (наиболее вероятный)

Разъём GPS работает как UART.

```text
JK-BMS (GPS)

GND ─────────────── GND ESP32
TX  ─────────────── RX ESP32
RX  ─────────────── TX ESP32
VCC ─────────────── не подключать (или только после проверки напряжения)

               ESP32
                  │
                  │
          MAX3485 RS485
                  │
                  │
      Daxtromn CN2 (Pylontech)
```

## Вариант 2

Если порт GPS переведён в режим RS485:

```text
JK-BMS RS485
        │
        │
ESP32 + MAX3485
        │
        │
Daxtromn RS485
```

## Проверка интерфейса

Перед разработкой прошивки рекомендуется определить фактический режим работы порта GPS.

Подключение FT232RL:

```text
FT232RL           GPS

GND ------------ GND
RX  ------------ TX
TX  ------------ RX
```

**VCC не подключать.**

Проверить обмен на скоростях:

- 115200
- 57600
- 38400
- 19200
- 9600

Если данных нет, открыть официальное приложение JK-BMS и проверить, появляется ли обмен на последовательном порту.

## Если GPS-порт является UART

Используются два UART ESP32:

```text
UART0
↓

JK-BMS

UART1
↓

MAX3485

↓

Daxtromn
```

## Рекомендуемый порядок работ

1. Определить тип интерфейса GPS-порта.
2. Снять и записать пакеты обмена JK-BMS.
3. Описать формат протокола JK-BMS.
4. Построить таблицу соответствия JK → Pylontech.
5. Реализовать шлюз ESP32.
6. Проверить работу с инвертором Daxtromn.
